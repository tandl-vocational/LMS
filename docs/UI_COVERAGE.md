# UI確認範囲

この段階の目標は、4ロールの画面・入力フォーム・遷移をそろえ、外部サービスなしでレビューできることです。

## 共通

- ロール別サイドメニュー、スマホ用メニュー・下部ナビゲーション
- URLによる画面移動、ブラウザの戻る操作、旧URLからの誘導
- モーダルのEscape・背景クリックによる終了、キーボードフォーカス制御
- デモの申請・回答・採点・ユーザー・教材編集を画面移動後も保持
- デモデータのリセット、空一覧、入力エラー、読込中・読込失敗の表示
- AI入力アシストの依頼・下書き・コピーのプレビュー

## 検証シナリオ

`npm run test:ui` は画面入口48件、スマホ表示10件と、以下の21シナリオを検証します。

1. ダッシュボードから学習画面への移動とブラウザの戻る操作
2. 添付付きの出欠申請
3. 事務局による理由付き差し戻しと必須入力
4. 学習者への差し戻し理由表示
5. 検定申込と事務局の受理
6. 応募状況の追加とキャリア面談の予約
7. 学習者の質問と講師の回答
8. クイズ不正解時のロックと100点での解禁
9. 課題提出→講師の最終評価→学習者への評価表示
10. アンケート回答と事務局の回答確認
11. 教材の選択と発注確認
12. 帳票プレビューとCSVダウンロード
13. アカウント作成とCSV取り込み・画面移動後の保持
14. CSVの重複拒否
15. 過去バージョンの復元確認
16. 新規コースの入力内容を画面移動後も保持
17. 教材ビルダーのステップ追加・JSON出力・受講生プレビュー
18. 支払い完了のデモ表示と決済履歴の更新
19. 会議の開始・終了時刻の検証と学習者への予定表示
20. 管理者ログインからMFA入力・ロール別ダッシュボードへの移動
21. スマホ用メニューから出欠申請フォームへの移動

## 次の工程で接続・確定するもの

- Supabase認証・MFA検証、RLS、データ保存、Storageへの実アップロード
- 受講登録・担当科目との関連、実際の学習進捗と出席率の計算・運用ルール
- Geminiの応答・一次採点、講師確定後の評価保存
- Stripe決済・Webhook、LINEアカウント連携・通知、会議サービスの接続
- Yjs/Supabase Realtimeによる同時編集、実データの履歴保存・復元
- 行政指定のExcel/PDFテンプレート、正式な検定申込用紙、修了証の発行ルール

これらはUIレビューを妨げませんが、実運用の動作が完成したことを意味しません。現在表示している時刻、コース、出席率、AI評価などにはサンプルデータが含まれます。
